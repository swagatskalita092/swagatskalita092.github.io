02 / Systems

FlashBuy

A split-brain failure. A fencing-token fix.

A flash-sale checkout backend built around one rule: stock can never be oversold, no matter how many buyers hit it at once. I used row-level locking, idempotency keys, and leader election to enforce that — then killed the leader, Redis, and Postgres mid-sale on purpose to see if it would hold.

FastAPI · PostgreSQL · Redis · Locust

Chaos-tested

  • Fix: epoch fencing token

03 / Data

Survey Pipeline

Protecting publication from silently wrong data.

An Airflow and dbt pipeline over 154,000+ real Stack Overflow Developer Survey responses. It publishes through a candidate/publish pattern, so a bad or partial run can never become the public answer. I tested that by running six real failure injections against the live stack by hand.

Airflow · dbt · PostgreSQL · Docker

04 / Methodology

Fullproof Project Toolkit

A repeatable method for interview-ready engineering.

The actual method behind the three projects above, written down as a public repo so anyone can follow it: name the risks first, build in phases, test it adversarially, document the results honestly. It's packaged as thirteen Claude skills and nine docs, with a tagged v1.0.0 release, and now a standalone Claude Code agent that can run the whole pipeline on its own and hand back one verified report.
