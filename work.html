ClearScan

Software Engineer · clearscan.fyi · Apr 2026 — Present

ClearScan is a real, live resume-scoring and job-matching platform, not a portfolio demo. I built and run it end to end. The scoring engine is deterministic: scikit-learn TF-IDF over a 137-skill taxonomy and 62 O*NET job profiles, with a hand-set calibration curve so the same input scores the same way every time. It runs on Supabase Auth and PostgreSQL with row-level security, and Stripe Checkout handles payments with signed, idempotent webhooks across nine event types. Two AI-assisted features, bullet rewrites and cover letters, are free to use and apply an LLM on top of that deterministic core rather than replacing it.

FlashBuy

Flash-sale checkout backend

A checkout API for limited stock that a lot of people want at once. The rule it has to hold: stock can never be oversold, no matter how many buyers hit it at the same time. It uses row-level locking (SELECT FOR UPDATE), idempotency keys, a Redis-backed waiting room with token-bucket admission, and leader election across replicas with an epoch fencing token - that last piece got added after someone pointed out a split-brain gap in an earlier version.

A later piece proves a different rule: once an order is confirmed, a completely separate fulfillment service, with its own database and no shared transaction, has to find out reliably. That's a transactional outbox: confirming an order writes its event in the same commit as the status change, a dedicated publisher only marks it sent once RabbitMQ confirms receipt, and the consumer keeps its own idempotent inbox so a duplicate delivery never becomes a duplicate job. Chaos-testing it against the real containers, publisher crash, consumer crash, a sustained broker outage, a poison message, found and fixed four real bugs along the way.

What actually broke, and what caught it

That's commit a512729. A second bug, a post-commit false-failure race (e20d769), turned up and got fixed the same way. In chaos testing, I killed the leader, Redis, and Postgres mid-sale by hand: zero duplicate orders came out of it, though killing Redis did lose the in-memory waiting-room state, which I've documented rather than hidden.

Stack Overflow Survey Pipeline

Analytics pipeline over two real survey years

An Airflow and dbt pipeline over 154,000+ real Stack Overflow Developer Survey responses from 2023 and 2024. The rule it has to hold: a bad or partial run can never become the published answer. It uses a candidate/publish pattern with a per-year monotonicity guard, CI that runs against hand-calculated fixtures, and a live static dashboard that regenerates from whatever's actually been published.

Fullproof Project Toolkit

Public methodology, skills & agent, v1.0.0, DOI-archived

This is the actual phase-by-phase method behind the three projects above, written down so anyone can follow it: pick an idea, name the risks, make provisional design decisions, build in verified phases, test adversarially, verify independently, and document honestly, bugs included. It ships as nine docs, thirteen importable Claude skills, a seven-domain idea bank, and two full idea-through-resume worked examples, with a real CI check that runs on every push. I also packaged the core methodology as a standalone Claude Code agent, a second production use of applied AI alongside ClearScan: it runs the whole pipeline on its own and hands back one verified report, dispatching a genuinely separate agent for its own second opinion and verification steps instead of just checking its own work.
